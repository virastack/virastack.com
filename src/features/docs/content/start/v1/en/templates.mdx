<h2 id="framework">Framework choice</h2>

The CLI offers two main frameworks; both have equal priority:

- **<GuideStackIcon icon={<NextjsIconDark className="dark:invert" aria-hidden />}>Next.js</GuideStackIcon> App Router**: Server Components, Turbopack, React Compiler. The i18n template with next-intl is kept separate.
- **<GuideStackIcon icon={<TanstackLogo />}>TanStack Start</GuideStackIcon>**: type-safe routing and SSR. Uses Paraglide JS for i18n.

Multi-language support isn’t stripped from code; it’s provided via **separate templates**. When the CLI asks “Do you want multi-language support?”, the matching template is copied:

- `templates`: plain (single language)
- `templates-i18n`: includes locale routing and translation infrastructure, with messages in the root `messages/` folder

<h2 id="testler">Tests</h2>

Every template ships with `Vitest`, Testing Library and MSW ready to use.

- `vitest.config.ts` and `src/test/`: jsdom setup, a `renderWithProviders` helper and an MSW server that fails on unhandled requests.
- Example tests in the landing feature: a helper (`get-initials.test.ts`), an API function with MSW (`get-users.api.test.ts`) and a component (`CartDemo.test.tsx`).
- `pnpm test` runs once and `pnpm test:watch` keeps watching. CI runs the tests before the build. See [scripts](/start/docs/v1/scripts).
