<h2 id="ne-zaman">When this applies</h2>

This page only applies if you chose multi-language support at install time (the **templates-i18n** copy). Plain templates have no locale routing. Template overview: [templates](/start/docs/templates).

<h2 id="nextjs"><GuideStackIcon icon={<NextjsIconDark className="dark:invert" aria-hidden />}>Next.js</GuideStackIcon> (next-intl)</h2>

Config lives in `src/i18n/routing.ts`. The scaffold ships with `en` and `tr`.

- `locales` / `defaultLocale`: which languages exist and which one is the fallback (`en` by default).
- Copy lives in `src/messages/en.json` and `src/messages/tr.json` (loaded via `src/i18n/request.ts`).
- `localePrefix: "as-needed"`: the default locale has no URL prefix (`/`); others use `/tr/…`. Only the URL decides the language, with no automatic redirect.

For APIs and patterns beyond this scaffold, see the [next-intl docs](https://next-intl.dev).

<h2 id="tanstack"><GuideStackIcon icon={<TanstackLogo />}>TanStack Start</GuideStackIcon> (Paraglide)</h2>

Locales are defined in `project.inlang/settings.json`. Routing uses the optional `{-$lang}` segment under `src/routes/`.

- `baseLocale`: the default language (`en` by default). `locales`: all locales.
- Messages live under `src/messages/{locale}.json` (for example `src/messages/en.json`).
- The default locale has no URL prefix (`/`); others use `/tr/…`, set by `urlPatterns` in `vite.config.ts`. Only the URL decides the language, with no automatic redirect.

For Paraglide details, see the [Paraglide JS docs](https://inlang.com/m/gerre34r/library-inlang-paraglideJs).

<h2 id="varsayilan">Change the default language</h2>

If you want to make another language the default:

1. **Next.js**: set `defaultLocale` in `src/i18n/routing.ts` (for example `"tr"`). With `as-needed`, the new default loses its URL prefix.
2. **TanStack Start**: set `baseLocale` in `project.inlang/settings.json`, then swap the prefixed and unprefixed locales in `urlPatterns` in `vite.config.ts`.
3. Update product copy in the matching message files. Keep `site.config` / SEO locale fields consistent if you expose them.

To add a new language, register it in the locale list, create its message file, and expose it in the language switcher. See the next-intl or Paraglide docs for details.
