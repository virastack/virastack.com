<DocsProse>

ViraStack AI 1.3.2 writes `.mdc` rules into `.cursor/rules/`, plus `AGENTS.md`, `CLAUDE.md` and an architecture guide in `docs/`. It detects Next.js or TanStack Start from `package.json` and writes only that framework’s rules.

<h2 id="install">Install</h2>

<CodeBlockCommand {...convertNpmCommand("npx @virastack/ai@1 init")} />

`@1` pins the last 1.x release. Without it, npm installs v2.

<h2 id="options">Options</h2>

<div className="overflow-x-auto rounded-lg border border-border">
  <table>
    <thead>
      <tr><th>Flag</th><th>Description</th></tr>
    </thead>
    <tbody>
      <tr><td className="whitespace-nowrap">`--force, -f`</td><td>Overwrite existing rule files without prompting.</td></tr>
      <tr><td className="whitespace-nowrap">`--framework <name>`</td><td>Set the framework explicitly (`nextjs` or `tanstack`).</td></tr>
      <tr><td className="whitespace-nowrap">`--tr`</td><td>Turkish prompts and success messages.</td></tr>
    </tbody>
  </table>
</div>

<h2 id="rules">Rules</h2>

Rules for the detected framework, written to `.cursor/rules/`. `nextjs.mdc` is for Next.js, `tanstack-start.mdc` for TanStack Start:

- `api.mdc`
- `core-principles.mdc`
- `forms.mdc`
- `i18n.mdc`
- `nextjs.mdc`
- `performance.mdc`
- `react-best-practices.mdc`
- `state-management.mdc`
- `tanstack-query.mdc`
- `tanstack-start.mdc`
- `testing.mdc`
- `typescript.mdc`
- `ui-components.mdc`

<h2 id="files">Files</h2>

<pre><code>{v1Tree}</code></pre>

`AGENTS.md` is written for the detected framework; with Next.js it starts with the Next.js agent block. Existing files are overwritten only after you confirm or with `--force`.
