<h2 id="tree">File tree</h2>

<pre><code>{tree}</code></pre>

Rule files are only written for the tools you select. `AGENTS.md` and `.virastack/ai.json` are always written.

<h2 id="agents-md">AGENTS.md block</h2>

ViraStack AI owns only the part between the `BEGIN:virastack-ai` and `END:virastack-ai` markers:

<pre><code>{agentsBlock}</code></pre>

- **Commands** use the package manager found from your lockfile (`pnpm lint && pnpm typecheck`, `npm test`, …).
- **Precedence** says your own project instructions override ViraStack rules, and framework docs decide API facts.
- **Rules** lists where each tool reads the rules and a table of every rule with when to use it.
- Your own text above or below the block, and the <AcademyBadge kind="nextjs" label="Next.js" /> block (`BEGIN:nextjs-agent-rules`), stay byte for byte.
- If the markers are unbalanced or repeated, the CLI stops and leaves the file as it is, so you can fix it by hand.

<h2 id="claude-md">CLAUDE.md</h2>

With `--agent claude`, `CLAUDE.md` gets an `@AGENTS.md` import line so <AcademyBadge kind="claudeCode" label="Claude Code" /> reads the block. The file is created if it does not exist; otherwise the line is added at the top and the rest stays. `remove` undoes exactly what was done. If `CLAUDE.md` is a symlink to `AGENTS.md`, the link stays and no line is added.

<h2 id="manifest">Manifest</h2>

`.virastack/ai.json` records what was installed. Commit it and do not edit it by hand.

<h2 id="managed">What is managed</h2>

ViraStack AI creates, updates and removes only these:

- Rule files inside the `virastack/` folders. Each starts with a “Managed by @virastack/ai” comment.
- The `virastack-ai` block in `AGENTS.md` and the manifest.
- The `@AGENTS.md` line in `CLAUDE.md`.

Anything else, including your own rule files next to the `virastack/` folders, is never touched.
