Şablonun her değeri değiştirilebilir:

```ts
definePolicy({ preset: "mfa" }) // 8 karakter, ikinci faktörle
definePolicy({ require: { digit: true } }) // bileşim kuralı, mecbursan
definePolicy({ blocklist: ["acme", "acme pay"] }) // parolanın tamamı ürün adın olamaz
definePolicy({ normalization: "NFC" }) // NIST'in önerisi; varsayılan NFKC
definePolicy({ blockCommon: false, blockRepetitive: false })
```

Çakışan kurallar (örneğin `maxLength`'ten büyük `minLength`) politika tanımlanırken hata fırlatır.

<h2 id="sonuc">Sonuç</h2>

```ts
import { evaluate } from "@virastack/password/strength"
import { policy } from "@/lib/password-policy"

evaluate("correct horse battery staple", policy)
// {
//   score: 0,            // 0–1 politikayı geçmez, 2–4 geçer
//   level: "weak",       // "weak" | "fair" | "good" | "strong"
//   length: 28,          // normalleştirme sonrası karakter (code point)
//   valid: false,
//   checks: { minLength: true, maxLength: true, notCommon: false, ... },
//   issues: ["password.common"],
// }
```

Geçerli bir parola en az uzunlukta `fair`, 5 karakter fazlasıyla `good`, 10 karakter fazlasıyla `strong` olur. Büyük harf, rakam veya sembol seviyeyi değiştirmez: NIST bileşim kurallarını kaldırdı, gösterge de onları geri getirmez. Tekrarlanan karakterler az katkı yapar. Kırılma süresi tahmini değildir.

**Karmaşık bir 14 karakterlik parola neden zayıf?** Skor evrensel bir kurala değil, politikaya göre hesaplanır. Varsayılan `nist` şablonu 15 karakter ister; daha kısa parolalar ne kadar karışık olursa olsun politikayı geçemez ve 0–1 alır. 15 karakterden sonra skor uzunlukla artar. Daha kısa parola mı gerekiyor? `mfa` şablonunu kullan: parola ikinci bir faktörle kullanılıyorsa NIST 8 karaktere izin verir.

<h2 id="forbidden">forbidden</h2>

Paket kullanıcını bilmez; değerleri sen verirsin. NIST'in istediği gibi parolanın tamamı karşılaştırılır, içinde kelime aranmaz: parola bir değer ya da onun bir parçasıysa (etrafında rakam, sembol, leetspeak veya tekrar olsa da) reddedilir. Büyük/küçük harf ve aksan yok sayılır.

```ts
evaluate(password, policy, { forbidden: [email, name, username] })
// "hello@virastack.com" → "hello" (alan adı yok sayılır)
// "Vira Stack" → "virastack", "vira", "stack"

// Rakam, sembol, leetspeak ve tekrar çıkarıldıktan sonra parolanın tamamı karşılaştırılır:
evaluate("vira-1990-2024!", policy, { forbidden: ["Vira Stack"] }) // containsPersonalInfo
evaluate("v1ra-v1ra-v1ra-2024", policy, { forbidden: ["Vira Stack"] }) // containsPersonalInfo
evaluate("viral-garden-path", policy, { forbidden: ["Vira Stack"] }) // geçer
```

Sıradan bir kelimenin içindeki kısa bir ad eşleşme sayılmaz: `Ali` adıyla `kaliteli-sabah-kahvesi` geçer, `ali1990` geçmez. `minTokenLength`'ten (varsayılan 3) kısa parçalar yok sayılır.

<h2 id="unicode">Unicode</h2>

- Parola varsayılan olarak NFKC ile normalleştirilir; farklı klavyelerde yazılan aynı metin, tam genişlikli harfler dahil, aynı sonucu verir. `normalization: "NFC"` NIST'in önerisine uyar; tam genişlikli harfleri ve bitişik harfleri olduğu gibi bırakır. Değiştirmek hash'lenen parolayı değiştirir; kullanıcın olmadan önce seç.
- Uzunluk code point sayar: bir emoji veya Türkçe harf bir kez sayılır.
- Sıfır genişlikli karakterler uzunluğa sayılmaz.
- `maxLength`'te hiçbir şey kesilmez; uzun parola `password.tooLong` alır.
