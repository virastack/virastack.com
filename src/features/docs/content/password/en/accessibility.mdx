<h2 id="aria">ARIA attributes</h2>

```html
<input id="virapassword-input-:r0:" type="password" aria-describedby="…-strength" />
<button
  type="button"
  aria-label="Toggle password visibility"
  aria-pressed="false"
  aria-controls="virapassword-input-:r0:"
/>
```

- `type="button"`: the toggle never submits the form.
- `aria-pressed` tells screen readers whether the password is shown; `aria-controls` links the button to the input.
- The label is in English; translate it through btnProps:

```tsx
useViraPassword({ btnProps: { "aria-label": t("togglePassword") } })
```

<h2 id="odak">Focus</h2>

- A mouse or touch press returns focus and the caret to the input.
- Enter or Space on the focused button keeps focus on the button.
- Safari skips buttons on Tab unless "Tab to all controls" is on; Option+Tab reaches them. That's a browser setting, not a bug.

<h2 id="canli">Live region</h2>

Spread `strengthProps` on the element that shows strength. Announce a short level, not every rule, so typing isn't noisy.

```tsx
const { inputProps, strength, strengthProps } = useViraPassword({ policy })

<input {...inputProps} />
<p {...strengthProps}>{strength?.level}</p>
// role="status" aria-live="polite" aria-atomic="true"
// the input gets aria-describedby pointing at it
```

<h2 id="caps">Caps Lock</h2>

`capsLock` is true while Caps Lock is on and the input has focus. Show a text hint; colour alone isn't enough.

<h2 id="ids">Stable IDs</h2>

Without `id`, the input gets one from `useId()`, which matches between server and client. Pass `id` when a label or test needs a fixed value.
